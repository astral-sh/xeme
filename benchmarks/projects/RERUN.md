# Run the real-project benchmarks

For baseline/candidate/Expat comparisons, use the [performance iteration
guide](../HILLCLIMB.md). The commands below compare two libraries; `--baseline`
optionally adds a third library to the native runner and matched consumer builder.

Run these Linux commands from the repository root, with absolute paths to the
candidate and reference shared libraries. Keep the corpus, executables and
source unchanged during measurement. Reserve one CPU for timing and use a new
output directory for every run.

```console
taskset -c 0 python3 benchmarks/projects.py \
  --library /absolute/libxeme_expat.so \
  --reference /absolute/libexpat.so \
  --corpus benchmarks/projects/corpus-manifest.json \
  --build-manifest /absolute/candidate-build.json \
  --output /tmp/xeme-native-projects
```

The default runs seven randomized pairs, twenty parses after a discarded warmup, both namespace modes, and 4/64 KiB feeds. Add `--preflight-only` to check complete normalized callbacks without timing.

## Python consumers

Use CPython 3.12.13 and its unmodified source at commit
`3bb231a6a5dc02b95658877318bf61501a7209e9`. The builder records source, command,
binary and library hashes. The worker loads the built extensions and checks the
resolved parser library before measuring.

```console
python3.12 benchmarks/build_project_consumers.py \
  --library /absolute/libxeme_expat.so \
  --reference /absolute/libexpat.so \
  --source /absolute/cpython-3.12.13 \
  --header include --output /tmp/xeme-project-consumers

taskset -c 0 python3.12 benchmarks/python_projects.py \
  --consumers /tmp/xeme-project-consumers/build.json \
  --corpus benchmarks/projects/corpus-manifest.json \
  --output /tmp/xeme-python-projects
```

Both ElementTree and pyexpat use namespaces. Seven randomized pairs each measure ten parses after a warmup, at both feed sizes. Every sample must produce the complete expected tree or event list. Add `--preflight-only` for validation alone.

## Complete Wayland commands

The pinned, unmodified Wayland scanner sources and their manifest are available in Git history. Extract only `wayland-scanner-source` to a temporary directory. The builder checks every source hash and compiles two scanners with the same flags; optional libxml DTD validation is disabled for both.

For a shallow clone missing this commit, first run `git fetch origin fe31da9b4050dfc901aa2fbd1080cb558e1c9f3f`.

```console
wayland_source_root="$(mktemp -d)"
git show fe31da9b4050dfc901aa2fbd1080cb558e1c9f3f:benchmarks/results/2026-09-10/real-project-baseline/evidence.tar.gz \
  > "$wayland_source_root/evidence.tar.gz"
tar -xzf "$wayland_source_root/evidence.tar.gz" -C "$wayland_source_root" \
  wayland-scanner-source

python3 benchmarks/build_wayland_project.py \
  --source "$wayland_source_root/wayland-scanner-source" \
  --consumers /tmp/xeme-project-consumers/build.json \
  --header include --output /tmp/xeme-wayland-build

taskset -c 0 python3 benchmarks/wayland_project.py \
  --build-manifest /tmp/xeme-wayland-build/build.json \
  --input benchmarks/projects/corpus/wayland/wayland.xml \
  --output /tmp/xeme-wayland-project
```

This measures complete `client-header` and `private-code` commands, including startup, input, parsing, code generation and output writes. All generated bytes must match between libraries. The default is seven randomized pairs of ten independent processes per command.
