# Isolated real-project optimization candidates

These immutable checkpoints retain original source archives, exact library hashes, benchmark samples, exhaustive scanner oracles, independent reviews and compatibility observations. Each archive excludes native binaries and identifies them by hash. Results measure native callback-driver parsing on pinned project XML, not full application execution.

- `composed-utilities-and-names` preserves the position/character-scan and bounded name-reuse composition on the DOCTYPE checkpoint, plus the original scanner screen. Its recorded small namespace regressions motivated the later threshold experiment.
- `raw-byte-count` preserves the five-line native UTF-8/ASCII length optimization and its independent compatibility/performance comparisons.
- `element-tag-scan` preserves the original, 32-byte and 64-byte prefix candidates on the same raw-length baseline. The final 64-byte prefix improved all 24 project medians in that cohort; its geometric-mean gain was about 10%, and about 2% against the original scanner in the same cohort. Different cohorts are retained separately.

All original 4,740 API outcomes remain 4,065 passing / 675 failing in these isolated candidates. The root integration and its additional attribute fixes are validated separately. No zero-failure or production-readiness claim follows from these screens. Each `files.json` verifies every archived member; original source reviews distinguish read-only review from executed validation.
