# Rejected position and entity optimizations

These candidates remain excluded. Each study retains its own earlier source and baseline identity; none is included in the current runtime.

- A short-span byte position loop passes 7,735,056 standalone comparisons but increases instructions on both measured project workloads. It was rejected before wall-time or broader runtime testing.
- Skipping anchored-source coordinate updates reduces instructions on a generated markup-entity fixture, but the intended fixture is slower in the paired timing screen. All real-project and generated measurements remain present. The private Debug representation also changes even though public anchored coordinates do not.
- Compact entity declaration summaries save allocations and about 4.9% of instructions in a declaration fixture, but real-project timing is neutral (0.9984× geometric speedup; 10/24 conditions positive). New adapter/event state was not justified. The first candidate also retains inflated capacity from numeric-reference spellings; its repaired version restores retained-byte parity, yet still fails the performance selection gate.

The archive includes complete patches and source snapshots, original failures, repaired candidates, profile and raw timing records, API comparisons, allocation traces and independent review. Binary files are represented by hashes. Each author's manifest was verified before packaging. Successful bounded correctness checks do not make a performance candidate worth adopting.
