# Compatibility and performance before rebase — 2026-09-13

The first independent project evaluation misses our 1.20× Expat target.
The strict compatibility differences below remain.

## Tested source

This pre-rebase evaluation tested runtime [`ec4d068`](https://github.com/astral-sh/oriole/commit/ec4d068bdb70b3bb19f9d11d31b31ed919ac27ba).
Changes through `bc784f1` affected tooling, workflows and documentation. These measurements predate the Xeme rename and later parser changes; they do not qualify the rebased runtime.
Comparisons use merged baseline `fe31da9` and Expat 2.8.4. Full source revisions
and library hashes are in the [compact results](2026-09-13-review.json).

## Correctness and adversarial checks

- **489 Rust tests pass**, with workspace Clippy and formatting checks. Tooling
  checks include 29 Python tests, Ruff, ty and 16 benchmark-harness tests.
- **4,740 API configurations:** Expat passes all; Oriole passes 4,349 and retains
  exactly 391 known failures. Of these, 366 concern allocation retry/schedules,
  12 literal version strings, 12 buffer policy and one deferral-growth assertion.
- **6,003 W3C rows per engine:** both retain 960 mandatory failures; no acceptance
  or loaded-child differences. Matching Expat does not establish catalog conformance.
- **2,718 differential cases:** no acceptance, error-code or normalized-event
  differences; 12 exact callback-fragmentation and 84 position differences remain.
- **Local differential fuzzing:** 23 retained replays and 2,974,362 generated
  executions, plus 10 initialization executions, in a bounded 301-second run.
  No mismatch or failure artifact. This local run used no sanitizer because the
  local Ohm ASan runtime was unavailable.
- **[CI fuzzing](https://github.com/astral-sh/oriole/actions/runs/34758172896/job/103726114929):**
  all seven targets pass on ARM64 Linux: 4,603,052 generated executions plus 265
  initialization executions. The new differential target accounts for 2,489,492
  generated executions. Commands use cargo-fuzz 0.13.2's verified ASan default;
  the logs do not directly attest compiler sanitizer flags or binary symbols.
  The separate C reference oracle uses an ordinary release build.
- **[CI compatibility and Miri](https://github.com/astral-sh/oriole/actions/runs/34759013089):**
  the corrected probe setup passes all three complete gates and both callback
  Miri modes, alongside platform, ABI and CPython consumer checks.
- **[Installed CPython/PBS](https://github.com/astral-sh/oriole/actions/runs/34759013064):**
  distribution structure, parser identity and XML gates pass on the host and
  glibc 2.17. Both discover the complete 803-case inventory and report
  `run=802 failures=2 skipped=13`. The raw upstream runner exits 2 for exactly
  `BufferTextTest.test1` and `CDATAHandlerTest.test_handlers`; the assertion gate
  and separate semantic check exit 0. The glibc 2.17 check also completes 1,024
  threaded parses. The preserved distribution is a generic x86-64, non-PGO build.

Fuzz execution counts include inputs filtered out of oracle scope; they are not
counts of actual Expat comparisons. The oracle target covers UTF-8, DTD-free XML
up to 8,192 payload bytes, excludes encoding declarations and resource-limit
errors, and uses a 10-second input timeout and 1,536-MiB RSS cap. It supplements
the other encoding, entity, allocation and parser-family targets. Bounded fuzzing
and Miri cannot establish exhaustive safety. Exact assertion baselines and
resource-policy differences remain in the [compatibility contract](../compatibility.md).

## Performance

Both campaigns use the [hill-climbing protocol](../../benchmarks/HILLCLIMB.md):
seven matched, randomized process rounds on shared-host Linux x86-64 CPU 0;
20 native or 10 Python measured parses after one discarded warmup per process.
Oriole uses O3, ThinLTO, one codegen unit and generic x86-64; Expat uses GCC O3
without LTO. No PGO or allocator change was introduced. CPython uses unmodified
3.12.13 `pyexpat` and ElementTree extensions built identically against each library.
These are parser/consumer measurements, not full application or installed-PBS timings.

| Corpus / consumer | Conditions | Oriole / baseline | Oriole / Expat | Slower than baseline |
| --- | ---: | ---: | ---: | ---: |
| Six tuning projects, C | 24 | 1.0156× | 1.1906× | 21 |
| Six tuning projects, CPython | 24 | 1.0005× | 1.0489× | 10 |
| Five independent projects, C | 20 | 1.0114× | **1.7867×** | 14 |
| Five independent projects, CPython | 20 | 0.9937× | **1.2158×** | 7 |
| Generated controls, tuning epoch | 16 | 1.0014× | 1.4671× | 7 |
| Generated controls, holdout epoch | 16 | 1.0011× | 1.4781× | 6 |

Aggregates are equal-weight geometric means of per-condition median paired
ratios. Every project contributes four conditions: 4/64 KiB feeds with namespace
off/on for C, or ElementTree/pyexpat for Python. Counts of slower conditions use
the observed ratios; they do not establish statistically significant regressions.
Generated and tuning results never enter the holdout aggregates.

The holdout **misses the 1.20× target on both native and combined Python aggregates**.
The merged baseline
already has most of this gap; the review changes add 1.14% native time in this
epoch. Native project means are 3.129× for Qt, 2.583× for LibreOffice, 1.611× for
MuseScore, 1.276× for Hadoop and 1.096× for .NET. The worst individual native
condition is Qt with 4 KiB feeds and namespaces enabled, at 3.257× Expat. The worst
Python condition is Qt/ElementTree with 64 KiB feeds, at 1.950×. These measurements
locate workload gaps; no profiling in this evaluation establishes their cause.
Across the ten conditions for each Python consumer, ElementTree takes 1.331×
Expat's time and pyexpat takes 1.110×.

The candidate selection note predates all holdout parser execution. Every
canonical preflight passed; no input was replaced or code retuned after seeing
results. The [frozen acquisition](../../benchmarks/holdout/README.md) retains
original input bytes and provenance. This corpus is now observed and can serve
as a regression set. A later independent performance claim needs new inputs.
Shared-host CPU affinity does not establish isolation or statistical significance.

## Reproduction and raw evidence

[Compact results](2026-09-13-review.json) bind the exact campaign reports, all
conditions and their source identities. [Tuning conditions](2026-09-13-tuning.csv)
and [holdout conditions](2026-09-13-holdout.csv) retain every row, including adverse
results.
The README's five rows use 4 KiB feeds with namespaces off: times are
medians of seven process medians; ratios are medians of the paired ratios and
need not equal the quotient of the displayed times.

The [evidence release](https://github.com/astral-sh/oriole/releases/tag/review-2026-09-13)
contains [review-qualification.tar.zst](https://github.com/astral-sh/oriole/releases/download/review-2026-09-13/review-qualification.tar.zst)
with raw benchmark workers, preflights, build records, compatibility and fuzz
results, and the tested CPython distribution. Verify the archive against the
SHA-256 in the compact results, extract into a fresh directory and follow its
`README.md`.
