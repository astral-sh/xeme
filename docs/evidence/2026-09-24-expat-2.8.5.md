# Expat 2.8.5 compatibility update

This update targets Expat commit `4b3f0b06f39fb5529cead381694f8929901bc273`
(`R_2_8_5`). It builds on Xeme's local review-stack tip
`66beebfcf55940d8c5e99ad2bee2632e4de8cee9`.

## Behavior and harness changes

The C adapter now applies the native `1.[0-9]+` version grammar to document and
text declarations, including after reset and in external children. Expat 2.8.5
uses the same grammar. The unshipped option for older permissive syntax and its
validation paths are removed. Accepted versions still use XML 1.0 semantics.

The decoder already rejected the malformed UTF-16 pairs fixed by
CVE-2026-93990. Native and C regressions now cover surrogate boundaries, ASCII and
markup after a high surrogate, both byte orders, and split input. The C tests
also cover BOM-free autodetection. No decoder implementation change was needed.

The reference, compatibility version, and fuzz-oracle greeting move to 2.8.5.
The public header marks `XML_SetHashSalt` deprecated. The upstream test adapter
routes private `xmlSetHashSalt` calls through the unchanged public API and
excludes the new private hash-table test. Expat's allocator-test fix supersedes
the local `memcheck.c` patch and reproducer, which are removed.

## Baseline review

The API inventory adds `test_utf16_surrogate_pairs`,
`test_xmldecl_wrong_version_number`, and `test_xmldecl_accepts_1_x_version`.
All three pass for both engines in all twelve configurations.

Existing failure allowances and configurations are unchanged. Assertion locations
were translated only where the upstream assertion source line was unchanged:
`basic_tests.c` shifts by 341 lines and `nsalloc_tests.c` by two lines. The
allocation adapter's source hashes were refreshed after reviewing the upstream
diffs; its 84-test inventory and assertion adaptations are unchanged.

The original baseline allows 509 API failures. This run observes 495, with the
same fourteen improvements already present on the parent stack: all twelve
`test_nsalloc_long_element` configurations and the two whole-buffer
`test_alloc_realloc_subst_public_entity_value` configurations. No new failure
allowance was added. The baseline's `source_revision` still identifies its
original Xeme source, rather than this reference update.
