# Compose real-project parsing optimizations

Four separate implementation commits add block XML-character validation and long-span position tracking, bounded element-name reuse, native UTF-8/ASCII byte counting, and bounded start-tag scanning with a 64-byte scalar prefix. Original independent candidate reviews, rejected/mixed screens and exhaustive scanner evidence remain in [hotpath candidates](../../../../benchmarks/results/2026-09-10/hotpath-candidates/). All four patches applied without manual conflicts after iterative attribute expansion and corrected attribute semantics.

The frozen root release passes **300 Rust checks**, strict Clippy/formatting, **1,518 exact ordinary comparisons**, **6,468 unchanged attribute observations**, **372 exact custom-attribute conditions**, **384 unchanged malformed-attribute observations**, **2,392 malformed-text comparisons**, **32 streaming/default/context/resume conditions**, and **36,456 exact custom-encoding comparisons**. All **4,740 upstream API outcomes** remain **4,065 passing / 675 failing**. Six shared/static C sanitizer suites pass with **333 selected-allocation failure scenarios per linkage**. C sanitizers cover callers; Rust is uninstrumented and leak sanitizer is disabled.

The native three-engine screen compares this root build, its exact preceding root build and Expat across six pinned projects, both namespace modes, 4 KiB/64 KiB chunks and two generated controls. Complete project callback preflights pass; every timed callback hash/count matches across engines. Five randomized pairs and seven parses per process show a **13.1% geometric-mean project improvement**, with every project condition **6.8–23.6% faster** than the parent. Oriole still takes **2.86× Expat's time** across the 24 project conditions. Shared-host load/frequency are uncontrolled; this measures native callback-driver parsing, not full applications.

The [actual CPython screens](../../../../benchmarks/results/2026-09-10/python-hotpath-screens/) use separately frozen candidates and identify their different compatibility bases. No sustained-fuzz, PBS, or production-readiness claim is made for this new runtime.
